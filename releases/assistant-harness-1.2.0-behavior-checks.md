# Read-only behavior checks

These are two independent model invocations against the proposed installed skill files, not cloud-plugin or unattended execution tests. Both were isolated from external accounts and instructed not to write. Source files were read directly; this does not prove native skill-reader availability.

## Continuity request

Input: continue implementation of an already mapped delivery project, using the repository's synthetic legacy JSON example, and report source roles and what could actually be verified.

Observed output: selected `recover`; read only core, configuration reference and supplied example. It did not load project-review machinery merely because implementation resumed. It identified delivery and implementation as the relevant roles, while noting that the synthetic JSON had no delivery mapping, routing policy, project identifier or implementation pointer. It refused to treat the placeholders as live account authority or claim verified project progress. No external call or write occurred.

Files read: `skills/outer-harness/SKILL.md`, `references/configuration.md`, and `examples/assistant-harness/config.example.json`.

## Migration boundary

Input: migrate hourly knowledge and Gmail event tasks when IDs, prompts, cadence, timezone, enabled state and conversation IDs were known, but runtime, delivery settings and full Gmail filters were omitted; also ask whether installation permits retiring legacy paths.

Observed output: blocked both migrations on incomplete metadata. It required retaining Gmail's event registration, declined prompt shortening before mapping all obligations and overrides, and kept legacy paths until verified consumer migration. It proposed complete private snapshots, actual runtime loading/read/write/repeat/failure checks, prompt-only edits of the same registrations, exact readback and later independent execution. No external call or write occurred.

Files read: core, scheduled-task, knowledge and project references.

## Limits

The checks establish observed interpretation of these two prompts only. They do not prove every workflow, automatic activation, native/cloud loading, mutable account behavior, message deduplication or independent execution. Remaining runtime gates retain their existing delivery issues.
